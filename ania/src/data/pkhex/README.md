# Data derived from PKHeX

Nothing in this folder is written by hand: it is all generated by `tools/extract-pkhex-data.ts`
from [PKHeX](https://github.com/kwsch/PKHeX), and overwritten wholesale every time that runs.
`sprites.json` is generated by `tools/extract-sprites.ts`, which also assembles the image sheets
in `public/pkhex/`.

It sits apart from the rest of `src/data/` precisely so that the boundary is visible: `../index.ts`
is ANIA+ code that reads these files; these files are not.

## What's here

| File | What it is |
|---|---|
| `personal.json` | Base stats, types, abilities and groups for every species |
| `learnsets.json`, `eggmoves.json`, `machines.json`, `tutors.json`, `special-tutors.json` | Where each move can come from |
| `evolutions.json`, `experience.json`, `categories.json` | Evolutions, experience curves, legendaries and mythicals |
| `movepp.json`, `movetypes.json`, `statusmoves.json` | PP, type and power of moves |
| `helditems.json` | Items that can be held |
| `g4chars.json` | Gen 4 character table, for reading and writing the names in the save |
| `i18n/<language>/` | Names of species, moves, items, abilities, natures and types |
| `sprites.json` | Cell index for the sprite sheets |

## Why they aren't transcribed by hand

They are tens of thousands of values. Copying them is a guarantee of typos, and a typo here doesn't
produce an error: it produces an illegal Pokémon that the game rejects without saying why. The
extractor pulls them out of PKHeX itself and checks what it pulls; if PKHeX is ever updated, it's
enough to run it again. How to do that is in the main README, under "Regenerating the Gen 4 data".
